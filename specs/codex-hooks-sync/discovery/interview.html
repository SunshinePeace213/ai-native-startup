Round 1 · what gets built

D1The destructive guard's nine ask-tier rules under Codex

They deny. One script, one host flag in the hooks.json command; the nine rules exit 2 under Codex with the "ask the user to run it via the ! prefix" fix line they already carry. Claude's ask tier is untouched.

Rules out mirroring the script unchanged — Codex parses permissionDecision: "ask" but doesn't support it, so it marks the run failed and runs the command anyway. Also rules out a permissions.allow layer: both permission systems match a command prefix, the guard matches a regex anywhere in the line.

D2Finding the edited file when tool_input.file_path doesn't exist

A shared edited_paths(payload) -> list[str] — the Claude path, or the *** Add/Update/Delete File: paths parsed out of the apply_patch envelope. All six write-surface hooks loop over it.

Rules out a key-rename shim: Codex sends a multi-file patch, not a path under a different name, so callers have to become path-list consumers. Mirroring every write-surface hook — not only the security ones — is what keeps a secret written through apply_patch from going unscanned.

D3Branch or fork when behaviour differs per host

One host-adaptive script per hook. Host differences are registration differences plus a flag. Nothing is duplicated into .codex/hooks/.

Rules out per-host variants, which would double every catalog, regex, and test for the two hooks that actually diverge — the drift that pointing Codex at .claude/hooks/ exists to prevent.

D4What .codex/config.toml pins

The Auto preset with network off — workspace-write, on-request, [features] hooks = true — and a check proving the hooks run offline from a warmed uv cache.

Rules out opening project-wide egress to protect one uv cache, and rules out approvals_reviewer = "auto_review" as an unattended stand-in for the lost ask tier: extra model calls per escalation, judged against a policy that isn't ours.

D5Prior art to port from

None. The apply_patch envelope parser is written from the grammar; the plan authors no Reference map.

Recorded so the plan doesn't reopen it.

Round 2 · how you'll know it works

D6Where each hook's Codex disposition lives

A CODEX_DISPOSITIONS dict in test_wiring.py is the source; every entrypoint must appear in it. hooks.md's catalog gains a Codex column, and a test asserts the column agrees with the dict. Vocabulary: mirrored / not-applicable / blocked-<reason>.

Rules out parsing the markdown table as the source (a reflowed row would break the suite for a non-reason) and rules out a dict alone (the catalog an agent actually reads would never mention Codex).

D7Driving real Codex sessions, and what counts as evidence

A committed probe script, run by hand — one codex exec --dangerously-bypass-hook-trust per mirrored hook against its real trigger, asserting the block happened. Output goes into implementation-notes.md. Pytest keeps pinning registration only.

Rules out a pytest integration suite that needs Codex auth, exceeds the 45s subprocess ceiling, and goes permanently red without the CLI. A human still runs /hooks once for real sessions — the probes bypass the trust gate, they don't replace it.

D8A failed $(git rev-parse --show-toplevel)

Nothing changes. uv errors, Codex reports a hook failure and continues — fail-open, which is the contract. Stated in the parity record so it isn't re-litigated. resolve_root() gains no cwd tier.

Rules out inventing a ${CODEX_REPO_ROOT:-…} convention nobody sets, and rules out failing closed, which would put one hook against the contract every other hook follows.

D9statusMessage and timeout on every entry

statusMessage everywhere, enforced by the generalised pin. Explicit timeout only on the four formatters and stop_sweep; pure-inspection guards keep the default.

Rules out accepting Codex's 600s default on hooks that shell out to real formatters, and rules out demanding a guessed number on hooks whose duration is bounded by construction.

Assumptions the build should challenge

  • Codex hooks run outside the sandbox. The docs never say. If they don't, uv may be blocked from its cache under ~/.cache/uv and every mirrored hook fails open silently. Caught by the first probe that should block and doesn't; fixed by adding the cache to writable_roots.
  • A warmed uv cache makes the hooks fully offline. Rests on dependencies = [] everywhere and a Python 3.12 interpreter already present.
  • The apply_patch envelope grammar is stable enough to parse. The docs give the field, not a formal grammar.
  • --dangerously-bypass-hook-trust faithfully reproduces a trusted run. A hook could pass its probe and still stay silent in a normally-trusted session.
  • The nine denied families aren't needed by Codex agents here. Codex runs review subagents and occasional implementation in this repo.
  • Claude's Bash permission rules are prefix-matched. Asserted from the Codex side — no Claude Code settings page is in the KB. Under D1 no permissions block gets written, so nothing depends on it.

Out of scope

  • Worktree hooks — Codex has no such events.
  • The spec gate — command-scoped; Codex has no per-command hooks.
  • file_guard's Read/Grep surface — Codex has neither tool; reads go through Bash, which bash_guard already intercepts.
  • A permissions.allow allowlist on either host — solves prompt noise, not the ask tier.
  • .codex/rules prefix rules — prefix-only matching, and they govern only commands leaving the sandbox.
  • Duplicating scripts into .codex/hooks/.
  • A PermissionRequest hook — a Codex event with no Claude side to mirror. Follow-up plan.
