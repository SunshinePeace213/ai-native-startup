This plan points .codex/hooks.json at the existing .claude/hooks/ scripts, adapts the two behaviours that genuinely differ across hosts, and makes the parity impossible to lose again.

Four things a live Codex session settled

The discovery ledger carried these as open assumptions. Rather than inherit them, planning ran throwaway sessions against codex-cli 0.145.0. Two findings changed the plan.

Resolved

Hook subprocesses run outside the sandbox

The ledger's largest risk was that hooks run sandboxed, blocking uv from its cache under ~/.cache/uv and silently failing every hook open. They don't. With the sandbox confirmed active, the agent's own $HOME write was blocked while a hook's succeeded in the same session. No writable_roots change is needed, and that planned work is dropped.

sandbox: workspace-write [workdir, /tmp, $TMPDIR] agent → touch $HOME/.probe_agent_write AGENTWRITE_BLOCKED hook → touch $HOME/.cache/uv/... can_write_uv_cache=yes hook → uv run --script python 3.13.13, offline OK
Changed the plan

The patch envelope has a fourth directive: *** Move to:

The ledger listed Add, Update, and Delete. A rename emits *** Update File: <old> followed by *** Move to: <new>. A formatter keyed on the old path would format a file that no longer exists — and, the security-relevant case, file_guard.py would let an agent rename a file onto a protected path unchallenged. Both paths get checked.

*** Begin Patch *** Update File: /abs/oldname.txt *** Move to: /abs/newname.txt *** End Patch
Changed the plan

The nine ask rules never carried the !-prefix line

The ledger said the ask tier could exit 2 reusing its existing "run it via the ! prefix" fix line. It has no such line — all nine hints end in "approve only if X is intended", and that wording belongs to the deny tier. Under Codex the stderr is read by the model, which cannot approve anything, so each ask rule gains a host-neutral line instead.

Confirmed

"Ask" really does run the command anyway

The premise behind the whole ask → deny decision, observed directly: a hook returning permissionDecision: "ask" is marked failed and the command executes. Exit 2 blocks cleanly and hands its Fix: line to the model verbatim.

hook: PreToolUse Failed → echo ASKME-marker ran, printed ASKME-marker hook: PreToolUse Blocked → echo DENYME-marker never ran

Most likely to change first

Volatile decisions

Each shows the chosen path and the live alternative. Flip any you disagree with — the revision prompt at the bottom assembles itself from what you flip.

edited_paths() branches on payload shape, not a host flag

Volatility: high
Chosen

tool_name == "apply_patch" parses the envelope; a string file_path returns a one-item list. The host flag stays, but only the destructive guard reads it.

The payload already discriminates. A flag would be a second source of truth that can disagree with the payload in hand — and a flag typo would route a Codex payload down the Claude branch, returning nothing and silently skipping the scan.

Alternative

Gate on HARNESS_HOOK_HOST everywhere, exactly as the ledger framed it — one uniform mechanism for both behaviour changes.

Three copies of the parser, pinned identical by one test

Volatility: high
Chosen

The helper lands in all three family _common.py modules. A single parametrized test runs the same envelope corpus through all three, so they cannot drift.

The families already duplicate note(), read_payload(), and resolve_root() — this is the established convention. A shared module could only be imported via sys.path manipulation, which the hooks rule forbids.

Alternative

One shared .claude/hooks/_hostlib.py, imported with an explicit sys.path insert in each family's _common.py.

Codex ask-tier denials get a newly written fix line

Volatility: medium
Chosen

Each of the nine ask rules gains a host-neutral second line: "Ask the user to run this themselves." No mention of any host-specific affordance.

Telling a Codex agent to "approve" is an instruction it cannot follow, and the ! prefix is a Claude Code affordance with no verified Codex equivalent.

Alternative

Reuse the deny tier's existing "…via the ! prefix" wording verbatim on both hosts, accepting that it may name something Codex does not have.

Explicit timeouts on five entries only

Volatility: low
Chosen

60 s on each of the four formatters, 120 s on stop_sweep. Every other entry keeps the Codex default.

Codex defaults an omitted timeout to 600 s — ten minutes of a wedged formatter. Only hooks that shell out to real formatters or sweep real files can hang; pure command-inspection guards are bounded by construction.

Alternative

An explicit timeout on all thirteen entries, guessing a bound for the inspection-only guards too.

Acceptance evidence is a hand-run probe, not a green suite

Volatility: low
Chosen

scripts/codex-hook-probe.sh drives one real Codex session per mirrored hook and asserts the block happened. Run by hand; output pasted into implementation-notes.md.

Every hook fails open, so a session with no error is indistinguishable from one where the hook never ran. The pytest matrix proves an entry exists, never that it fired.

Alternative

A pytest integration suite driving Codex directly — accepting that it needs auth, exceeds the 45 s subprocess ceiling, and goes red on any machine without the CLI.

Mechanical detail — settled, listed for completeness
  • Every Codex command uses uv run --script "$(git rev-parse --show-toplevel)/.claude/hooks/…" and carries a statusMessage.
  • A failed git rev-parse yields an empty substitution, uv errors, and Codex reports a hook failure and continues. Fail-open by contract, stated so it isn't re-litigated.
  • resolve_root() gains no cwd tier: Codex never sets $CLAUDE_PROJECT_DIR, so it falls through to Path(__file__).parents[3], which is correct.
  • Stop ignores matchers entirely; SubagentStop matches on agent_type. Both are registered with none, which matches all.
  • The probe script lives at scripts/codex-hook-probe.sh, deliberately outside .claude/hooks/ — anything with a shebang under that tree needs a registration or the wiring test fails.
  • No new dependencies; all 15 entrypoints already declare dependencies = [].
