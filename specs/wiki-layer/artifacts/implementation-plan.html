A layer that remembers what every plan learned

The KB caches official docs faithfully and forgets everything we concluded about them. This plan adds the missing layer: ai-docs/wiki/, an LLM-maintained synthesis wiki over the immutable mirrors, with four operations, one schema rule, and a privacy boundary made of git semantics rather than good intentions.

The pattern, as this repo will run it

Three layers, one of them new

Mirrors already exist and never change. Answers already happen and never persist. Everything this plan builds sits in the middle band.

Layer 1

Mirrors — immutable, device-local

~50 cached official pages under ai-docs/, registered in sources.yaml, fixed only by refetch. This plan reads them and touches nothing.

↓ /wiki:ingest reads a mirror, never edits one

Layer 2

The wiki — compiled synthesis, tracked in git

Domain folders over one shared schema at ai-docs/wiki/. Tracked through gitignore negation because synthesis is compiled knowledge, not regenerable cache. personal/ is re-ignored and never leaves this machine.

↓ /wiki:query reads pages, writes nothing

Layer 3

Answers — cited, status-flagged, disposable

Every answer names its pages and carries their status inline. An answer worth keeping gets crystallized back into layer 2 by running an ordinary ingest on it.

Most likely to change first

Volatile decisions

Six calls that a reasonable reviewer could make differently. Flip any of them to see the consequence in the specimen page, and to build the revision prompt at the bottom.

Seven frontmatter fields, three status values

Volatility: high
Chosen

type, domain, status, created, updated, sources, related — with status: current | superseded | disputed travelling into every answer. A disputed claim is flagged where it is cited, never dropped.

Lint and Dataview both need consistent fields, and status propagation is the one convention the graphwiki source found actually prevents silent drift.

Alternative

A lean three-field schema — type, domain, sources — dropping dates, status, and links until lint proves they are read. Cheaper to write; answers lose the ability to flag contested claims.

Privacy is a gitignore negation, not a second vault

Volatility: high
Chosen

!ai-docs/wiki/ tracks the wiki; ai-docs/wiki/personal/ re-ignores the private domain, which keeps its own local-only personal/index.md and personal/log.md. The shared index and log never name personal content.

One vault root, one Obsidian config, one schema — and the cloud lint routine works from a fresh clone that structurally cannot see personal/.

Alternative

A separate personal vault outside the repo. A harder boundary, at the cost of two vaults to run, two configs to keep in sync, and no shared linking.

Slash commands plus a path-scoped rule

Volatility: medium
Chosen

.claude/commands/wiki/{ingest,query,lint,status}.md and .claude/rules/wiki-layer/wiki-standards.md, which loads whenever a session touches ai-docs/wiki/**.

These are deliberate user-triggered passes, like /kb. The official docs steer new work toward .claude/skills/; repo convention wins and the conflict is recorded rather than forked.

Alternative

Skill-first under .claude/skills/, following the docs. Model-invoked rather than typed, which trades predictable invocation for automatic engagement.

AC7 gates on committed fixtures, run three times

Volatility: high
Chosen

Two related fixture articles and a rubric ship under checks/fixtures/. The build lead runs ingest → ingest → query → lint in three fresh sessions; run 1 starts from the seed, runs 2–3 re-run to exercise idempotency. Pass rate 3/3, evidence per run in implementation-notes.md.

Command bodies are prose — nothing structural proves they work. The eval tier requires a pass rate, and a single green run proves nothing.

Alternative

Gate on the user's own fresh-article Web Clipper migration instead — the original design. More realistic capture path, but it cannot run pre-ship, so "done" would depend on work outside the build.

Four operations, expansion behind triggers

Volatility: medium
Chosen

ingest · query · lint · status. absorb arrives when the unprocessed backlog passes ~10, breakdown when lint repeats the same missing page, cleanup when its fix list needs its own pass — each via the direct lane. Status derives all three triggers from tracked state.

Smallest surface that still schedules lint; expansion follows demonstrated need rather than anticipated need.

Alternative

Ship absorb and breakdown in v1 so the backlog and page-splitting paths exist before they are needed.

Wiki-first lives in AGENTS.md, capped at 14 lines

Volatility: low
Chosen

The Knowledge Base bullets name the wiki index before the mirror index, the durability rule routes gate-passing synthesis into /wiki:ingest, and a Wiki Layer section registers the commands. Schema stays in the rule file.

AGENTS.md loads every session, so every added line is paid for on every task. A session-start hook is deferred behind the "sessions demonstrably skip the wiki" trigger.

Alternative

A SessionStart hook that injects the wiki index into every session, making wiki-first mechanical instead of instructional.

Mechanical detail

Exact contracts — gitignore, log entries, command stamps
  • The gitignore block appends after the existing ai-docs rules: !ai-docs/wiki/, then ai-docs/wiki/personal/, then !ai-docs/.obsidian/ with ai-docs/.obsidian/workspace* ignored. Existing mirror rules are untouched.
  • Log entries are ## [YYYY-MM-DD] <op> | <title> | <source-path> with <op> ∈ ingest|lint. Lint adds the payload line missing-pages: … · mechanical-fixes: N — the fields status derives its breakdown and cleanup triggers from. Only ingest and lint write.
  • Command stamps come from the rule's operations table: ingest opus/high, query sonnet/high, lint opus/high, status haiku/medium. argument-hint appears on ingest and query only.
  • ai-docs/.obsidian/app.json sets attachmentFolderPath to wiki/assets and alwaysUpdateLinks to true; the vault root is ai-docs/.
  • Linking is [[wikilinks]] between wiki pages and ordinary markdown links to mirrors and repo files, so citations still render on GitHub.
  • The weekly lint routine is created once post-ship via /schedule: weekly cron, fresh clone, lands fixes as a claude/-branch PR. Its exact prompt is documented in lint.md.
Edge cases already answered
  • Missing mirror on a fresh clone — lint reports "run /harness-layer:kb", never a broken citation.
  • External URL passed to ingest — refused, with a pointer to /harness-layer:kb add <url>. Sources become mirrors first.
  • Duplicate ingest — idempotent on the canonical source path; pages update in place and a second identical run changes nothing.
  • Personal attachments — moved under wiki/personal/assets/; local lint flags any personal page referencing files outside personal/.
  • Contradiction during ingest — both claims flagged disputed with cross-references; resolution flips the loser to superseded. Nothing is deleted.
  • Query outside coverage — say the wiki doesn't cover it. Never guess, never silently fall back to the mirrors.
  • Cloud lint versus the personal domain — the fresh clone has no personal/, so routine output must not claim to have linted it.
  • Empty wiki — query and status degrade gracefully on the seed; lint reports clean, not errors.
  • Concurrent edits — re-read any page immediately before editing; single-writer assumption is recorded.

Guardrails and non-goals
  • Additive only — no edits to mirrors, ai-docs/index.md generation, sources.yaml semantics, or any harness-layer command file.
  • Commands stay under .claude/commands/wiki/. Do not move them to .claude/skills/ mid-build.
  • No pre-created domain folders and no placeholder pages beyond the two seed files — folders appear on first ingest.
  • Out of scope: absorb/breakdown, hybrid-search CLI, embeddings or vector store, session-start hook, team sharing, multi-agent wiki writes, the enterprise RAG stack.
  • Command bodies are instructions, not rationale — no design history, no cross-references the operation doesn't need to run.
