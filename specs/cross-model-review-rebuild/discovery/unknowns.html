Section two

The vocabulary you're missing

You said you don't know the standards for review. There is a real field here with settled language. These seven terms are the ones your harness is missing — each one names a mechanism that would have stopped a loop you actually hit.

Severity vs. blocking

How bad it is, versus whether it stops the merge.

Severity is a property of the defect (critical / high / medium / low). Blocking is a policy decision about that severity. Mature review systems keep them separate so a reviewer can say "this is real, it is medium, ship it and track it."

Your two skills only emit approved / changes-requested, and define advisory as "never changes the verdict." So a reviewer who finds something real has exactly one lever: block. That is why Codex blocks every round.

Convergence & the scope ratchet

Whether the loop is guaranteed to end.

A terminating review is a contraction: each round must strictly shrink the open set. The classic failure is the scope ratchet — round N+1 raises a standard that round N did not apply, so the target moves as fast as the author hits it.

per-feature-harness-restructure rounds 1→4 are one continuous ratchet on validator strictness: greps → self-contained greps → bounded-relationship greps → single-markdown-block greps. The standard rule is: a reviewer may only block on findings in the round-1 scope; anything new is filed, not blocked.

Definition of Ready / Done

The published entry and exit contract.

DoR is what a spec must contain before review may start; DoD is what makes it done. Both are checklists agreed in advance, so review is a conformance check against a fixed list rather than an open-ended hunt.

You asked "is my standard too vague?" — the honest answer is that you have a list of angles to look for, which is a hunting license, not a DoD. Angles have no completion state; a checklist does.

The code-health bar

Approve when it's better, not when it's perfect.

Google's published standard: a reviewer approves once the change definitely improves overall code health, even if it is not perfect. "There is no such thing as a perfect change" is stated policy, and reviewers mark non-blocking comments as nits.

Pair it with a named tie-break owner. Every real review system names who decides when author and reviewer disagree — otherwise disagreement is resolved by exhaustion, which is exactly what your 7-round run was.

Property-based & fuzz testing

Machine enumeration of an unbounded input class.

When correctness spans an infinite input space — parsers, matchers, permission guards — you do not review your way to confidence. You state an invariant ("no glob may select a protected path") and let a generator attack it thousands of times per second.

Rounds 2–7 were a fuzz campaign executed by hand, at conversation speed, one input per round. A hypothesis property test would have produced the whole family in one run — and stayed in the repo as a regression net.

Phase containment

Was it caught at the stage that should catch it?

The standard measure of whether a review gate earns its cost: of the defects a stage should have caught, what fraction did it catch? Low containment at spec review means the spec gate is theatre and the cost belongs downstream.

Right now you cannot compute it — nothing records which build defects were foreseeable from the spec. That single number tells you whether spec review deserves two rounds, one, or zero.

Rule budget & eviction

A memory layer that forgets on purpose.

Any self-improving rule store grows monotonically unless something removes rules. Mature designs cap the store, attach an owner and a review date to each entry, and require a new rule to cite the incident that created it — so unused rules can be evicted with evidence.

This matters more than usual here: Anthropic's Claude-5 context-engineering guidance reports removing over 80% of Claude Code's system prompt with no performance loss, and names over-specification and repeated instructions as the failure mode. An append-only rule layer optimises against the model generation you just migrated to.

The bar professionals judge a review system by

Six numbers, not opinions

  • Rounds to approve — median. Healthy is 1–2. Yours is 3–7.
  • Finding precision — share of blocking findings that survive scrutiny. Low precision teaches authors to argue instead of fix.
  • Phase containment — defects caught at the stage that owns them. Tells you what spec review is worth.
  • Escaped defects — what reached main anyway. The only measure of whether the gate works at all.
  • Scope-ratchet rate — blocking findings raised after round 1 that were in scope at round 1. Should be near zero.
  • Cost per merged PR — wall-clock and tokens. The budget you're currently breaching without measuring.
