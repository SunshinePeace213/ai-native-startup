Implementation plan · Issue #80

A design studio that stops at the signed handoff

Soriza sells design but runs it from memory. This plan turns a client engagement into eight phase commands with gates that can actually fail — and hands the finished layout over without writing a line of the site.

Reviewed across four rounds. The Codex gate raised 52 findings, 32 of them blocking. All are fixed. Two changes mattered most: agent teams are gone entirely — a plain subagent already lacks the lead's conversation history, so the one teammate bought no isolation while silently breaking the roster's effort stamps — and the component inventory became a client-signed P3 artifact whose hash the P6 gate re-verifies. The round-4 fixes were not re-verified by a fifth round; the cap is two per run.

Most volatile · gate mechanism

The component inventory is a P3 deliverable signed by the client, and the P6 gate re-verifies its hash

The matrix and contrast checks are only as honest as the list they quantify over. An inventory written at P6 alongside the matrix could omit nine of ten components and both would agree with each other. So it lands at structure/inventory.md as one of P3's deliverables, enumerated from the signed wireframes, with its SHA-256 in the P3 sign-off — and the p6 gate recomputes that hash, because a signature three phases back says nothing about the file P6 actually measures against.

Still live: a P6-authored inventory with no signature, relying on the design-QA agent to notice omissions. It loses because it makes the denominator self-declared — the exact vacuous pass these checks exist to prevent.
Most volatile · placement

The four check scripts — and the command-eval runner — live in .claude/scripts/studio-layer/

Anything with a PEP 723 header under .claude/hooks/ is treated as a hook entrypoint that must be claimed by a registration surface, and needs a Codex verdict. A check script a command calls has neither, so putting it there turns the wiring suite red.

Still live: a scripts/ folder inside the question-bank skill, on the meta-agent/scripts/validate_agent.py precedent. It loses because three of the four scripts serve commands, not that skill.
Volatile · contract

The gate hook takes the phase as argv[1], and the shared test fixture grows an args parameter

No hook in this repo has ever taken an argument, so run_hook launches scripts with nothing after the path and cannot exercise the new hook as registered. It gains args: tuple = (); every existing caller is untouched.

Still live: inferring the phase from the newest sign-off file, the way the spec gate infers its plan folder from mtime. It loses because a client project holds all eight phase folders at once, so mtime would gate the wrong phase.
Volatile · orchestration

Every role is a subagent — no agent teams anywhere

The draft kept one teammate for P2's cold-designer test, on the reasoning that a teammate does not inherit the lead's conversation history. That property is not teammate-specific: an ordinary subagent has its own context window too. So the teammate bought no isolation while adding the experimental agent-teams dependency — and broke the roster, since teammate reuse of a definition covers tools and model but not effort. Each role also sets disallowedTools: Agent, so "one level deep" is enforced rather than asserted.

Still live: teammates for P4's competing art directions, if a phase ever needs roles talking to each other. It would first require re-deriving how a teammate's effort is set, since it does not come from the agent file.
Settled · naming

Agent names are plain and layer-prefixed; the person opens the body

Claude routes off name and description, and name must be unique tree-wide. studio-art-director routes; Elena Ferraro appears in the body, where a persona belongs.

Still live: hybrid names like art-director-elena-ferraro. Rejected because it puts the persona back into the routing document the unknowns pass deliberately kept it out of.
Settled · reach

The question bank is a skill the roles invoke, with no disable-model-invocation

Preloading via skills: would no-op for teammates, and marking the skill user-invocable-only would put it out of reach of the very roles meant to use it. A check script re-derives the dimension list from the skill itself, so the bank is a mechanism rather than prose.

Still live: preloading the bank through each role's skills: frontmatter. Rejected — it silently does nothing in the teammate shape this plan allows.
Settled · staffing

Every build task stays on a Claude model

The roster would send parsers and matchers to gpt-5.6-sol, but the build command has no Codex implementation path — Codex enters this pipeline at review. The check scripts run on opus at high, and the Codex gate still judges the result.

Still live: stamping studio-check-scripts to gpt-5.6-sol. It would need the build stage to learn a Codex path first, so it is a change to the pipeline, not just to this plan.

What this will not do the scope fence

Twelve brainstorm cards were on the table; this plan builds nine. The three that are left are follow-on plans, not forgotten work.

  • No development work. The layer stops at a signed layout handoff. The P6 pack is what a builder consumes; building from it is somebody else's job.
  • No PRD. The P2 brief is the client agreement. /harness-layer:harness-plan stays the only thing that turns intent into a spec.
  • Card 10 — lesson graduation. P7 routes lessons to where they will load again; promoting a repeated lesson into a skill is a follow-on plan.
  • Card 11 — the design KB. No WCAG or ARIA mirrors this run; blocked on which prototype tool P5 commits to.
  • Card 12 — the first real run. Eight phases on a live brief is a usage run, not a diff, so it cannot be an acceptance criterion of a prompt-file PR.
  • No client data committed. This plan adds the directory contract and the ignore rule, never a real client's files.
