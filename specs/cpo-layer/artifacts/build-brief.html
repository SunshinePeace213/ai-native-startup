The layer's whole thesis is in this row: a phase either advises or it blocks. P2, P3, P4 and P6 register check_gate_signoff.py in their own frontmatter with their own phase token, so a hard gate cannot close while the sign-off file is missing, a field is blank, or a recorded SHA-256 no longer matches the artifact it claims to approve.

        Deviation · three studio rules
        
The plan said paths: clients/**. The build shipped clients/**/*.

        

          studio-roster surfaced the split: it had written clients/**/*
          while the other two builders copied the literal plan text. Under the
          kb-grounded profile the tie-break is the mirror, not memory —
          ai-docs/anthropic/memory.md documents src/**/* as
          “All files under src/” and carries no bare dir/**
          row, so “clients/** matches nested files” had no citable source.
          Every path-scoped rule already in this repo uses the same form:
          specs/**/*, tests/**/*, .claude/hooks/**/*,
          **/*.py.
        

        

          Had the plan's form been wrong, nothing would have complained: no studio rule would ever
          load on a client project. AC5 asserts the substring clients/**, which
          clients/**/* contains, so no criterion and no locked decision changed —
          only the glob the plan spelled out in prose. Both affected checks re-ran clean after the
          change, and the two one-line edits were made by the builders owning each file.
        


$ bash specs/cpo-layer/checks/ac4-client-artifacts.sh   # exit 0
$ bash specs/cpo-layer/checks/ac5-rules-path-scoped.sh  # exit 0

      


      

        Pending red · closed
        
Could a directory contract survive being gitignored?

        

          AC1's check returned exit 1 on two counts on the builder's own run, both because
          clients/.gitkeep was still untracked — builders are barred from
          git add. The lead staged and committed it and the check went green
          with no file change, which is the outcome that proves the
          clients/* + !clients/.gitkeep pattern pair works:
          git check-ignore -v clients/acme/site/brief.md →
          .gitignore:378:clients/*, while
          git check-ignore -q clients/.gitkeep exits 1 — the negation
          re-includes the contract file.
        

      


      

        Contract · agreed between two builders
        
How does the coverage checker find the dimension list without keeping its own copy?

        

          Settled as a documented anchor rather than an inferred one: every ###
          heading under ## Dimensions is one dimension, and the heading text is its
          name — stated by the skill itself, in its own
          ## Machine-readable dimension list section. Eight dimensions today. The test
          that matters is the one showing that adding a dimension to the skill changes what the
          checker requires.
        

      


      

        Provenance
        
Whose contrast threshold is the contrast script enforcing?

        

          The script prints Soriza project threshold, so it never claims conformance to a
          specification this repo has not mirrored. The lead recomputed the pinned ratio
          independently rather than trusting the test's docstring:
          #8A837A on #FAF8F5 →
          L_fg=0.230410 L_bg=0.940514 ratio=3.5324, matching the asserted
          3.53:1. AC12's “the formula itself is checked, not just the
          branching” holds.
        

      


      

        Placement
        
Where do four check scripts live without reddening the wiring suite?

        

          .claude/scripts/studio-layer/, not .claude/hooks/ — so the
          wiring suite never sees them as unclaimed hook entrypoints. Only
          check_gate_signoff.py is a hook, and it earns its registration surface from
          the four gate commands.
        

      


      

        Hygiene
        
Does running the behavior eval leave scratch files in the PR?

        

          No. The meta-skills runner writes to
          …/studio-client-questions-workspace/, already covered by
          .gitignore:355 *-workspace/.
