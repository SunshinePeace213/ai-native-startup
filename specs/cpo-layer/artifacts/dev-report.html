Why AC16 is the one left open. It began the review as a disclosed gap: the commands suite scored 0.8889 against a required 1.0, and the build deliberately did not paper over it.

Three separate causes were untangled rather than lumped together. a3 demanded one literal phrasing the documented contract never requires. b4 was unfalsifiable — it asked a judge to confirm a process from artifacts that record no process. a5 was a fair assertion the command genuinely failed, so the command was fixed and the assertion left alone. The suite then reached 1.0.

Then round 2 invalidated that 1.0. The eval staged its scratch project as a plain directory, not a git repository — while the commands had just been re-anchored on $(git rev-parse --show-toplevel). So the graded agent had been using relative paths and the anchoring was never exercised. The runner now git inits each staged root, but the replacement rate could not be measured: all six invocations returned "You've hit your session limit". The 0.0 that produced is an artifact of the limit, not a defect — every deterministic check in those runs still exited 0.

03The review journey

27 findings across two Codex rounds plus a full security pass. Filter by severity or by how each was dispositioned.

I1-F3blocking The hard gates accepted any one signed artifact

The tests signed a single docs/<phase>-approved.md, so P2 could close with no brief or sitemap and P6 with no handoff pack.

Fixed — each gated phase names the rows its sign-off must list, hash-verified like any other. P2's set is brief + sitemap, matching the spec's own Gate column; the creative brief was deliberately excluded rather than making the hook demand what no command tells the principal to sign.

I1-F5blocking The revision counter never counted

Rows all numbered 1 never exceeded the allowance — verified against the pre-fix script, where three such rows against an allowance of 2 exited 0.

Fixed — round numbers must be positive, unique and contiguous from 1; anything else exits 2, because the count itself is meaningless.

I1-F4blocking The allowance came from an unsigned brief

Editing 2 to 3 silently bought a round. The existing test asserted that mutation as an allow path.

Fixed — the brief is refused unless sign-off/p2.md lists it and its SHA-256 still matches. The test was removed and split into one that proves re-derivation and one that proves post-signature mutation exits 2.

I1-F6blocking One change order bought unlimited rounds

Cost — rounds: 0 passed, and a single order could be referenced by any number of excess rounds.

Fixed — cost must be ≥ 1, and each order covers at most the rounds it declares. A 2-round order legitimately covering two rounds still passes, so this is capacity arithmetic rather than a ban on reuse.

I1-F9blocking Sign-off artifact paths were unconstrained

An absolute path, a .. segment or an escaping symlink could satisfy a client signature with a file elsewhere on disk.

Fixed — contained() requires the resolved target, symlinks followed, to sit beneath the resolved project root.

I1-F10blocking QA rows fell open

Only the exact pair blocking/open blocked, so blocking | TBD or a blank status handed over an engagement QA had not cleared.

Fixed — both cells are validated against their enums; a row the gate cannot read blocks rather than reading as resolved.

I1-F7 · I1-F8blocking Command paths and arguments

The four gate commands told multi-project users to run from inside PROJECT_DIR, where every repo-relative path in the same file misresolves; and PROJECT was unvalidated.

Fixed — bodies anchor on $(git rev-parse --show-toplevel), PROJECT must be two safe segments. See the lesson below: the first attempt used the wrong variable.

I2-F1blocking The eval environment was not the real one

A regression the round-1 fix introduced. The scratch project was not a git repository, so the freshly-anchored paths could not resolve — yet the suite scored 1.0, because the agent used relative paths instead. Confirmed directly: git rev-parse --show-toplevel returned fatal: not a git repository.

Fixed — the runner initializes each staged root hermetically, and a test expands the command's literal PROJECT_DIR: line inside it. That test is what would have caught this.

I2-F2blocking The replacement b4 was too permissive

It accepted three arbitrary headings, a sitemap copy one character different, and a single matching word from one triage row.

Fixed — a real structural difference (≥3 sections the plan names and the sitemap does not) plus traceability across at least half the triage rows. Proven against nine fixtures; the old check false-passed three of them.

I2-F3blocking Five criteria recorded two different results

The review lead's own error. The edit that rewrote each AC block's node ids inserted the new evidence paragraph without removing the old one, leaving 26/14, 12/9, 9/6, 7/6 and 17/7 side by side.

Fixed — stale paragraphs removed, then every AC command re-run and its claimed count compared against the observed one. All ten now agree.

I2-F4blocking The spec drifted behind the counter

The hardened counter demanded a hash-matching sign-off, contiguous rounds and per-order capacity while spec.md still said an existing change order sufficed.

Fixed — the contract now states what the code enforces, written as specification rather than changelog.

I1-F14…F18 · I2-F5advisory Robustness, folded into the same files

Loose allowance regex, IndexError on short rows, duplicate matrix rows hiding a blank one, stale workspace output, and ids that differ only in type.

Below the blocking bar, but fixed anyway — each sat in a file already being rewritten.

I1-F19 · I1-F20 · I1-F21 · I1-F22advisory Recorded, not fixed

The routed glob lesson grew the always-loaded rules 254→257 (the pipeline's own mandated memory step, and AC5's budget is 280); AC5's substring grep accepts clients/**bogus; P6's gate does not itself run the states and contrast checks; two module headers carry rationale.

Carried to the PR's Follow-ups rather than redesigned mid-review.

security 0 of 46 candidates survived

19 researchers → 46 candidates → 29 deduped → 13 through a three-lens adversarial panel (39 votes). Four TRUE votes, spread across four candidates; none reached the 2-of-3 quorum.

The verifiers converged on one fact: this is local, single-principal developer tooling where the would-be attacker either is the operator or already needs repository write access. Two caveats kept rather than smoothed: 16 candidates were never paneled (five are fixed anyway), and the tree was dirty while the scan ran.

04What was learned

Amendments and routed lessons — each lands where it will load again.

  • A check is evidence only if its harness reproduces the runtime environment → new standard 3 in impl-standards.md. Born directly from I2-F1: a 1.0 that measured the harness rather than the change.
  • Judge a command by its own exit status → standard 4. A pipe into tail reports the pipe's status; a trailing echo replaces it. The build hit the first form, this review hit the second.
  • CLAUDE_PROJECT_DIR is hook-scoped → hooks.md, beside the registration idiom that uses it. It resolves in a hook, an stdio MCP server and a plugin LSP server only. A fixer proposed it for command bodies and flagged its own doubt; the doubt was right — it is empty there, and the anchored path would have become /clients/… at the filesystem root.
  • The paths: glob form is <dir>/**/* → memory-series.md, routed by the build and retained here for traceability.
